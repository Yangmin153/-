# 여행길 v6 — 장소 수집 중심 개편

## 화면 흐름
여행지역 선택 → 지도 검색에서 연속 추가 → 최적 동선 만들기 → 지도 + 방문 순서.

- 지역을 고르기 전에는 편집 화면이 나타나지 않습니다. 지역 변경은 방문지·출발지·도착지를 유지합니다.
- 지도 제어 버튼은 지도 밖 툴바에 배치했습니다. 검색은 별도 전체화면이며 지도/목록을 전환합니다.
- 검색 입력은 250ms 지연, 이전 요청 취소, 최대 30개 검색어의 2분 캐시를 사용합니다. 장소 검색은 페이지당 15개, 최대 45개를 제공합니다(기존 API 한도).
- 출발·도착 검색은 전국에서 자유롭게 찾습니다. 주소 검색은 장소 API 장애와 별도로 동작합니다.
- 중복 추가를 차단하고 추가됨 버튼·장소 수·토스트로 결과를 알립니다.
- 배경 고정 및 스크롤 복원, 목록 내부 스크롤, visualViewport 높이, 키보드 포커스 이동, Escape/뒤로 가기, 동작 줄이기를 지원합니다.
- 결과 전에는 순서 번호가 없습니다. 결과 지도와 타임라인 번호는 동일합니다. 겹친 핀을 누르면 해당 장소들을 선택할 수 있습니다.
- 장소 변경 후 이전 번호·경로·총시간을 숨기고 재계산을 안내합니다. 계산 중 중복 요청을 막고 계산 도중 변경된 목록도 구분합니다.
- 날짜·출발시각·체류시간·수동 순서 이동·길안내 UI를 제거했습니다. 기존 저장 데이터의 날짜 필드는 보존하지만 표시하지 않습니다.
- 네이버 자동차 경로와 GitHub/Vercel 구조는 유지합니다. 대중교통은 미지원으로 비활성화하고 서버도 거부합니다. 추정 구간은 예상 시간·점선으로 표시합니다.
- 기존 회원 저장·파일 입출력·공유 링크는 유지합니다. 서버의 기존 저장 계약상 회원 저장에는 출발·도착이 필요합니다.

## 쉬운 문구
| 이전 문구 | 변경 문구 |
| --- | --- |
| 경유지 추가 | 방문지 추가 |
| 경로 최적화 | 최적 동선 만들기 |
| 출발지 지정 | 여기서 출발 |
| 최종 도착지 지정 | 여기로 도착 |
| stale 결과 | 방문지가 바뀌었어요 |
| 재최적화 | 변경한 장소로 다시 만들기 |
| 미지원 transport | 대중교통 · 아직 지원하지 않아요 |

## 코드 구조
- `public/static/app.js`: 지역 선택, 여행 상태, 저장 호환, 결과 화면
- `public/static/v6/model.js`: 중복 판별, 데이터 검증, 결과 변경 판별, 표시 함수
- `public/static/v6/search.js`: 전체화면 검색, 키보드/스크롤, 목록/지도, 연속 추가
- `public/static/v6/place-service.js`: 장소/주소 검색 결합 및 부분 장애 처리
- `public/static/v6/map.js`: 네이버 SDK, 지도 인스턴스, 경로 및 겹친 마커
- `public/static/v6/style.css`: 공통 디자인 시스템, 모바일 및 데스크톱 화면

중복된 v4/v5 화면 스크립트와 스타일을 제거했습니다. 옛 HTML 문자열을 검사하던 버전별 테스트를 새 흐름 테스트로 교체하고 기존 API·계정 소유권·데이터 테스트는 유지했습니다.

## 검증 범위
`npm ci && npm test`
- 단위/API 테스트: 계산, 추정 안내, 저장 데이터 호환, 중복, 결과 무효화, 시간 표기, 마커 그룹, 잘못된 입력, 계정 소유권.
- DOM 통합 테스트: 지역 선택 → 출발/도착 → 연속 추가 → 중복 방지 → 지도/목록 → 지역 변경 보존 → 계산 중복 방지 → 삭제 → 재계산.
- DOM 테스트는 모의 API이며 실제 지도 렌더링/기기 Safari·Chrome 검증을 대신하지 않습니다.
- Preview에서 네이버 지도 SDK 인증에 실패하면 네이버 콘솔의 Web 서비스 URL에 Preview 주소를 등록해야 합니다. 실제 도로 API/장소 API는 기존 Vercel 환경변수가 필요합니다.
