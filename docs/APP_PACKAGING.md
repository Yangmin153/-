# 여행길 모바일 앱 패키징 참고

이번 변경은 반응형 모바일 UI + PWA 기반 **앱 패키징 준비 단계**입니다. 모바일 브라우저와 실제 Android/iOS WebView 모두에서 인증·딥링크가 자동 보장되는 완성된 네이티브 앱은 아닙니다.

## 현재 준비된 것
- `viewport-fit=cover`, `100dvh`/`85dvh`, iOS/Android safe area, 하단 고정 액션과 접근 가능한 44px 이상의 터치 영역
- 앱 설치 기반 `manifest.webmanifest`, 아이콘, 시작 URL
- 기존 `/api/places`와 `/api/route` 요청 및 localStorage 키/일정 데이터 구조 유지
- OS의 공유 기능(Web Share API)과 HTTPS 클립보드 폴백, URL hash 기반 공유(서버에 저장하지 않음)
- 네이버 지도 앱 `nmap://route/car`(앱 식별자에 모바일 웹 원본 URL 사용) 및 브라우저 폴백

## 네이티브 앱 패키징 전 반드시 검증할 사항
1. **네이버 지도 JS SDK**: WebView 내 `file://`/로컬 오리진으로 직접 열면 서비스 URL 인증이 실패할 수 있습니다. 앱의 HTTPS 서버 origin을 유지하거나 네이버가 허용하는 앱·도메인 방식으로 인증을 구성하십시오.
2. **카카오/네이버 비밀키**는 Vercel 서버에만 보관하고 앱 바이너리, JavaScript, 저장소에 넣지 마십시오.
3. **iOS**: 외부 URL 스킴(`nmap`) 열기를 네이티브 App/Browser 플러그인 등으로 연결하고 사용 여부 조회 시 `LSApplicationQueriesSchemes` 구성을 확인하십시오.
4. **Android**: 외부 인텐트(네이버 지도 앱)를 외부 애플리케이션으로 열도록 WebView 외부 URL 처리 및 필요 시 `queries` 패키지 가시성 구성을 확인하십시오.
5. `nmap://` 설치 감지와 자동 웹 폴백은 브라우저가 완전한 설치 확인 API를 제공하지 않으므로 근사 처리입니다. 실제 앱 패키징 단계에서는 Capacitor 등 네이티브 플러그인으로 신뢰성 있게 처리하십시오.
6. 네이버 지도 웹 폴백은 구형 URL 쿼리 호환성이 변경될 수 있으므로 최신 지도 웹에서 출발·도착지 자동 입력 여부를 실기기 확인하고 필요 시 업데이트하십시오.
7. Web Share/클립보드/파일 다운로드/WebView 백 버튼/화면 회전/안전영역/키보드 올라온 상태를 iOS Safari, Android Chrome 및 패키징된 WebView에서 테스트하십시오.
8. 앱스토어를 통한 배포에는 스플래시/512x512+모바일 전용 아이콘, 개인정보 처리방침, 배포·심사 정책, 서비스별 API 데이터 재이용 조건 검토가 필요합니다.

## 제한사항
- 네이버 실시간 지도·길찾기와 카카오 검색은 네트워크가 필요합니다. 현재 서비스워커와 오프라인 지도 캐시는 의도적으로 제공하지 않습니다.
- URL 공유는 브라우저에서 제공하는 짧은 일정만 지원하며, 초과하는 일정은 기존 JSON 내보내기/가져오기를 이용합니다.
- 저장 장소 데이터의 보관 및 타사 지도 표시가 카카오·네이버의 각 API 이용 약관과 양립 가능한지 공개 전 검토해야 합니다.
