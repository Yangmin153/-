# 여행길 v2 · 네이버 지도 여행 동선 웹사이트

기존 FastAPI + 네이버 지도 API 개발 방식과 쉽게 연결할 수 있도록 만든 **독립 실행형 업그레이드 프로젝트**입니다. 기존 ZIP 파일을 직접 덮어쓴 것이 아닙니다. 실행 전 기존 프로젝트를 백업하세요.

## 가장 쉬운 실행 방법 (Windows 10/11)

1. ZIP 파일을 **압축 해제**하세요. 압축파일 안에서 직접 실행하면 안 됩니다.
2. 프로젝트 폴더의 `.env.example`을 복사하여 **`.env`**라는 이름으로 저장합니다. (Windows에서 확장자를 표시하는 것이 편리합니다.)
3. 기존 프로젝트에서 이미 사용 중인 네이버 클라우드 **Maps Client ID**와 **Client Secret**을 `.env`에 입력합니다. 필요한 API: Web Dynamic Map, Directions 5, Geocoding.
4. `start_windows.bat`을 더블클릭합니다. Python 3.11+가 설치돼 있어야 하며, **최초 실행 시 인터넷 연결**이 필요합니다.
5. 브라우저에서 <http://127.0.0.1:8000>을 엽니다. API 문서/테스트는 <http://127.0.0.1:8000/docs>입니다.

### `.env` 작성 예시

```ini
NAVER_MAPS_CLIENT_ID=기존_네이버_클라우드_클라이언트_ID
NAVER_MAPS_CLIENT_SECRET=기존_네이버_클라우드_시크릿
NAVER_MAPS_JS_KEY_ID=
NAVER_DIRECTIONS_URL=https://maps.apigw.ntruss.com/map-direction/v1/driving
NAVER_GEOCODE_URL=https://maps.apigw.ntruss.com/map-geocode/v2/geocode
```

`NAVER_MAPS_JS_KEY_ID`는 별도의 JS 지도 키를 쓰지 않는 경우 공란으로 두면 Client ID를 사용합니다. **Client Secret은 브라우저 코드에 넣으면 안 됩니다.** 지도 화면에서 인증 오류가 뜨면 네이버 클라우드 콘솔에서 서비스 URL (`http://127.0.0.1:8000` 등)과 API 활성화 여부를 확인하세요.

> 기존 앱이 구형 Directions 도메인을 사용하는 계정이라면 `.env`에서 `NAVER_DIRECTIONS_URL`만 기존 계정의 정상 동작 URL로 변경하여 호환할 수 있습니다. API 계약/권한은 계정별로 직접 확인이 필요합니다.

### 수동 실행 (macOS / Windows Terminal)

```bash
python -m venv .venv
# Windows: .venv\Scripts\activate
# macOS: source .venv/bin/activate
python -m pip install -r requirements.txt
python -m uvicorn app:app --reload --host 127.0.0.1 --port 8000
```

## 사용 순서

1. 위의 **DAY 1**, **DAY 2** 탭을 눌러 날짜를 선택합니다. `+` 버튼으로 새 날짜를 추가하면 전날 최종 도착지를 다음 날 출발지로 가져옵니다. 전날 도착지가 변경되고 다음 날 출발지가 여전히 같은 위치라면 자동으로 연동합니다.
2. **출발지**, **도착지**를 눌러 매일 서로 다른 위치를 지정합니다.
3. **+ 장소 추가**를 누릅니다. 다음 방법을 지원합니다.
   - **도로명/지번 주소 검색**: 네이버 Maps Geocoding API 사용. 관광지 이름 검색은 아님.
   - **지도에서 선택**: 네이버 지도를 한 번 클릭해 좌표를 얻고 장소 이름을 입력.
   - **좌표 직접 입력** 또는 **예시 위치** 선택.
4. 장소 카드 왼쪽 `⠿` 아이콘을 마우스/손가락으로 끌어 순서를 바꿉니다. 접근성 화살표 버튼도 지원합니다.
5. **자동 최적화**는 방문 순서를 다시 계산합니다. **내 순서 유지**는 현재 카드 순서를 바꾸지 않고 자동차 이동 경로만 계산합니다.
6. 장소를 고정하려면 장소 카드의 **위치 고정**에 체크합니다. 자동 최적화에서도 해당 순번은 유지됩니다.
7. 아래 **최적 동선 계산하기** 버튼을 눌러 지도·시간표·이동거리·체류시간을 확인합니다.
8. 일정은 이 브라우저의 `localStorage`에 자동 저장되며, 우측 상단의 **일정 저장 ↓**으로 JSON 백업을 할 수 있습니다.

> 예시 관광지 좌표는 UI 체험용 대략적인 지점입니다. 실제 여행에 사용하기 전 입구/주차장 위치 등을 확인하세요.

### 최적화 알고리즘의 정확한 의미

- **관광지 0~6곳 / 자동 최적화:** 방향이 있는 (출발→관광지, 관광지→관광지, 관광지→도착) 이동시간 행렬을 네이버 Directions 5 구간 요청으로 구성하고, 사용자 지정 방문 순서 고정 제약을 유지하면서 모든 후보 순서를 검사합니다. 모두 정상적으로 도로 이동시간을 받은 경우 **해당 시점 API 응답 구간 가중치의 합 기준으로 정확한 최소 경로**입니다.
- **관광지 7~12곳 / 자동 최적화:** API 요청이 지나치게 많아지는 것을 막기 위해 직선거리 기반 휴리스틱(시작 위치 선택 + 2-opt)으로 방문 순서를 만든 뒤 선택된 **각 이동 구간**을 네이버 실제 도로 경로로 조회합니다. **도로 이동시간 기준 전역 최적 경로를 보장하지 않습니다.**
- **내 순서 유지:** 장소를 재정렬하지 않고 각 구간만 조회합니다.
- **네이버 API 미설정·일부 구간 실패:** 별도 도로 데이터가 없는 구간은 명시적으로 **추정** 표시합니다. 직선거리×1.33, 가정 평균속도 42km/h의 교육용 값이며 정확한 운행 예측이 아닙니다.
- 이 앱의 네이버 길찾기 요청은 호출 시점 교통 조건을 이용합니다. 실제 도착시간을 보장하지 않으며, 장래 날짜의 교통량을 예측하는 서비스가 아닙니다.
- 왕복 일정도 자동으로 지원합니다. 출발지·도착지는 고정되고 그 사이 순서만 변경됩니다.

### 비용 주의

실제 네이버 Maps 경로 API에는 호출량 제한 및 유료 사용량이 적용될 수 있습니다.

- 관광지 4곳 자동 최적화: 보통 **최대 20개 구간 호출** (4개 출발→관광지 + 12개 관광지 상호 + 4개 관광지→도착), 중복 위치는 API 호출하지 않습니다.
- 관광지 6곳 자동 최적화: **최대 42개 구간 호출**.
- 관광지 7곳 이상 또는 수동 순서: 대략 **방문지 수+1**번의 요청.
- 일정 수정 후 기존 계산 결과가 있었다면 짧은 지연 후 다시 요청합니다. 사용량·요금을 확인하세요.

실제 상용 서비스를 개설하기 전에는 **서버 사용자 인증/요청 수 제한, 요금 상한, 모니터링, API 허용량, 이용약관 검토**가 필수입니다. 현재는 **개인용 개발·테스트 환경**에 적합합니다.

## 네이버 장소 검색 API에 관한 중요 사항

일반 **네이버 검색 API(지역 검색)**와 **네이버 클라우드 Maps Geocoding(주소 검색)**은 서로 다른 API입니다. 2026년 9월부터 적용된 검색 API 약관에는 검색 결과 가공, 복사·저장, 검색 API 데이터를 본래 목적 이외에 사용하는 데 제한이 있습니다. 여행 최적화에 검색 결과를 별도 데이터셋으로 저장·재가공하는 기능은 **법적/약관상 허용 범위 확인 전 포함하지 않았습니다.** 그래서 이 버전은 지도에서 직접 선택하거나 주소를 검색한 위치를 사용합니다. 상용 서비스의 관광지 이름 통합 검색은 사용 권한이 확인된 POI 제공자/데이터 라이선스를 선택해 추후 구현해야 합니다.

- 약관: https://developers.naver.com/products/intro/terms/terms.md
- Maps API 개요: https://api.ncloud-docs.com/docs/ko/application-maps-overview
- Directions 5: https://api.ncloud-docs.com/docs/ko/application-maps-directions5
- Geocoding: https://api.ncloud-docs.com/docs/ko/application-maps-geocoding
- Maps JS v3: https://navermaps.github.io/maps.js.ncp/docs/tutorial-2-Getting-Started.html

## 개발자를 위한 폴더 구성

```text
yeohaenggil_v2/
  app.py                  # FastAPI / Maps API 프록시 / 최적화 알고리즘
  web/index.html          # UI 화면
  web/styles.css          # 데스크톱/모바일 디자인
  web/app.js              # 일정 편집, 드래그, 지도 표시, 저장
  requirements.txt        # Python 설치 목록
  .env.example            # API 키 입력 양식 (.env는 커밋 금지)
  start_windows.bat       # Windows 실행
  tests/test_routes.py    # 자동 테스트
```

## 테스트

```bash
python -m pip install pytest
python -m pytest -q
```

현재 자동 테스트에는 기초 API, 날짜/도착시간 처리, 고정 방문지 순서, 입력값 검증, 초기 화면 제공이 포함됩니다. **네이버 실제 키 연결, 모바일 실기기 터치 제스처, 실제 도로 코스 정합성은 별도 검증해야 합니다.**

## 배포

FastAPI 한 서버에서 HTML/CSS/JS와 API를 동시에 제공하므로 단일 Docker 컨테이너에 배포할 수 있습니다. 운영 URL을 네이버 Maps 웹 서비스 URL에 등록하고, Client Secret은 서버의 환경변수/Secret Manager에 보관해야 합니다. 클라우드 서버를 별도 준비하지 않은 현재 상태는 로컬 실행만 지원합니다.
